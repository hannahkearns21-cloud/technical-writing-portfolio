# Editorial Decisions

This document explains selected changes made during the editing process. The goal was to make the instructions clearer, more concise, and easier for a beginner to follow while preserving the original meaning.

## 1. Reduced Wordiness

**Original:**

> GitHub repositories are something that is used by developers for storing code and other files and it also allows people to collaborate with other people on projects.

**Edited:**

> A GitHub repository stores your code, files, and project documentation. Repositories also make it easier to collaborate with others.

**Why:**

The original sentence is long and uses unnecessary wording such as "are something that is used by" and "collaborate with other people." I replaced it with shorter, more direct sentences that communicate the same information.

## 2. Removed Unnecessary Phrasing

**Original:**

> In order to create a repository, you will first need to have a GitHub account, if you don't already have one.

**Edited:**

> You need a GitHub account to create a repository.

**Why:**

"In order to" can be simplified to "to," and "if you don't already have one" is unnecessary. The revised sentence communicates the requirement directly.

## 3. Used Direct Instructions

**Original:**

> Once you are logged in, you will be brought to your homepage where you can find a plus sign in the top right corner of the page.

**Edited:**

> In the upper-right corner, select **+**, then select **New repository**.

**Why:**

The original describes what will happen to the user instead of directly telling them what to do. I changed it to an action-oriented instruction that is easier to scan and follow.

## 4. Improved Organization

**Original:**

> After clicking on New repository, you will then be taken to a new page where you will need to enter information about your new repository.

**Edited:**

> ## Create a Repository

**Why:**

The original sentence adds unnecessary information and delays the actual instructions. I added a heading to clearly separate the task from the prerequisites and make the guide easier to navigate.

## 5. Simplified Explanations

**Original:**

> A public repository can be viewed by anyone on the internet, while a private repository can only be viewed by you and people you give access to.

**Edited:**

> - **Public:** Anyone can view the repository.
> - **Private:** Only you and people you grant access to can view the repository.

**Why:**

I converted the information into a bulleted list so readers can quickly compare the two visibility options. This improves readability and makes an important distinction easier to understand.

## 6. Removed Repetition

**Original:**

> The first thing that you will need to do is enter a repository name. Your repository name should be something that describes what the repository is for.

**Edited:**

> Enter a name for your repository. Choose a name that clearly describes the project's purpose.

**Why:**

The original repeats "repository name" and uses the wordy phrase "the first thing that you will need to do." The edited version gives the instruction more directly.

## 7. Improved Technical Terminology

**Original:**

> After that, you will see an option that says "Add a README file."

**Edited:**

> Select **Add a README file** if you want GitHub to create a README file for your repository.

**Why:**

I formatted the interface label as bold text to distinguish it from the surrounding instructions. I also clarified what selecting the option does so that a beginner understands its purpose.

## 8. Added a Clear Conclusion

**Original:**

> You have now successfully created a GitHub repository and are ready to begin adding and managing your files.

**Edited:**

> Your GitHub repository is now ready. You can begin adding files, writing documentation, and managing your project.

**Why:**

The original uses "successfully" as unnecessary filler. The revised conclusion is more concise while providing a useful next step for the reader.

## Overall Editing Approach

The main goal of this edit was to make the guide more **direct, concise, scannable, and beginner-friendly**.

I focused on:

- Removing unnecessary words and repetition
- Using active, direct instructions
- Breaking long sentences into shorter ones
- Organizing information with headings and lists
- Clearly identifying GitHub interface elements
- Preserving the original meaning
- Making the instructions easier to scan and follow
